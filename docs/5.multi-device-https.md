# Sync across devices over HTTPS

[Scope and roadmap](functional-spec.md)

```text
Zotero A / Zotero B → HTTPS → Caddy → HTTP on loopback → rclone WebDAV → cloud storage
```

Run Caddy on the same always-on host as Bridge. The operator manages the hostname and proxy. Caddy obtains and renews the TLS certificate when the hostname and network meet its certificate requirements.

## Set up the host

1. In Bridge, connect your cloud provider. In **WebDAV → Advanced**, choose **Preferred port**, enter `18765`, and apply. Enable WebDAV and confirm that **Local WebDAV URL** shows `http://127.0.0.1:18765/`. If the port is occupied, choose another free port and use the same value for Bridge and Caddy.
2. Install Caddy on the Bridge host. Point a dedicated hostname at the host's public address and make TCP ports 80 and 443 reachable by Caddy for public HTTPS and certificate issuance. If the host is behind a router, forward those ports to the host. Keep the dashboard, the rclone control interface, and the WebDAV upstream port private.
3. From the repo root, start Caddy with [deploy/Caddyfile](../deploy/Caddyfile). Replace `dav.example.com` with your hostname and set `BRIDGE_WEBDAV_PORT` to the port shown in Bridge.

   ```sh
   BRIDGE_WEBDAV_HOST=dav.example.com BRIDGE_WEBDAV_PORT=18765 caddy run --config deploy/Caddyfile --adapter caddyfile
   ```

   If Caddy already runs on the host, add the site block to its existing configuration and set the same variables in the service environment. Keep Bridge, WebDAV, and Caddy running while devices sync. After reopening Bridge, enable WebDAV again.

Caddy proxies `/zotero` and `/zotero/*` to the loopback WebDAV server. It preserves the request method, path, `Authorization` header, and body. Other HTTPS paths return HTTP 404. Zotero uses the root of the dedicated hostname as its base URL and adds `/zotero/` automatically.

## Configure and verify each device

1. Sign in to the same Zotero account on each device. Under **Settings → Account → File Syncing → My Library → WebDAV**, enter `https://dav.example.com/` and use the WebDAV username and password shown in Bridge. If Zotero has a separate protocol selector, choose **https** and enter the hostname. Select **Verify Server**.
2. Import a new PDF as a stored attachment on device A and sync. On device B, sync and open the downloaded PDF. Zotero syncs the library records through its own service and transfers the attachment through WebDAV. Repeat with a large attachment and compare the downloaded file with the original.
3. From another device, verify that `/zotero/` rejects missing and incorrect credentials with HTTP 401 and that the dashboard route `/` returns HTTP 404 over HTTPS. Confirm the Bridge dashboard and WebDAV loopback ports cannot be reached directly from that device.
4. After sync finishes, close Bridge briefly. Verify that the HTTPS WebDAV route returns HTTP 502 while rclone is stopped. Reopen Bridge, enable WebDAV, and run **Verify Server** again.
5. Repeat verification and attachment transfers on each mobile client and version you plan to use.
