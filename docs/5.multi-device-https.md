# Sync across devices over HTTPS

[Scope and roadmap](functional-spec.md)

## Proposed code and deployment design

In this proposal, the operator configures a reverse proxy. Bridge continues to use `src/webdav.rs` for the loopback endpoint. The proxy terminates TLS and forwards requests.

```text
Zotero A / Zotero B
  → HTTPS, public URL
  → reverse proxy, WebDAV route
  → HTTP loopback, rclone serve webdav
  → configured cloud remote
```

- Use a fixed loopback port for the proxy upstream. If the port is already in use, WebDAV reports an error for the operator to resolve. The proxy continues to point to the configured port.
- Forward the HTTP method, WebDAV path, Authorization header, and request body. If the public URL uses a path prefix, check URL mapping in WebDAV responses and headers that contain URLs. Expose only the WebDAV route.
- The dashboard displays the address where rclone is listening. The operator gets the HTTPS URL for Zotero from the proxy configuration. The dashboard and rclone control interface keep their private addresses.
- After adding the route, run **Verify Server** from another device, then test uploads and downloads across devices over HTTPS. Also test missing credentials, incorrect credentials, large files, and proxy behavior when the upstream is stopped.

## Proposed processing flow

1. Install Bridge on an always-on host, connect a cloud provider, and enable WebDAV on loopback.
2. On the same host, run a reverse proxy that listens for HTTPS requests and forwards WebDAV paths to rclone. The proxy preserves WebDAV methods, paths, credentials, and request bodies. Only the WebDAV route is accessible remotely. The dashboard and rclone control interface use private addresses.
3. On each device, sign in to the same Zotero account, configure the same HTTPS URL and WebDAV credentials for the personal library, and run the device's verification step.
4. When device A uploads a file, the request passes through the proxy and rclone to the cloud folder. When device B syncs, Zotero retrieves library records through the Zotero service and attachment data from the same WebDAV endpoint.
5. Verify uploads and downloads across devices. Repeat on each selected Zotero mobile platform and version. Use another host to confirm that administrative ports and routes stay private.

## Decisions before implementation

Decide whether Bridge configures the proxy from the dashboard or the operator configures the domain, certificate, and proxy. Select the Zotero mobile platforms and versions to test.
