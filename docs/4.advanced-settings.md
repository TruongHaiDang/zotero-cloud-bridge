# Advanced settings

[Scope and roadmap](functional-spec.md)

## Proposed code design

`src/settings.rs` validates and saves configuration. When a change affects the endpoint, the service reuses the startup flow in `src/webdav.rs`.

```rust
enum PortPreference { Auto, Preferred(u16) }

struct SettingsUpdate {
    cloud_folder: String,
    port: PortPreference,
    credentials: CredentialsUpdate,
}

fn apply_settings(update: SettingsUpdate)
    -> Result<ApplyOutcome, ApplySettingsError>;
```

- Serialize `apply_settings` with WebDAV startup. Validate required fields, the port, and the path relative to the current remote. Check that the destination folder is accessible and apply the folder policy once it is approved.
- If the service is stopped, save the validated configuration for the next startup. If it is running and the folder, port, or credentials change, keep a copy of the current configuration, stop the old process, and start a new one with the updated settings.
- Commit the new configuration after the endpoint passes the readiness check. If startup or saving fails, clean up the new process and try to restart with the previous configuration. Report whether recovery succeeded so the dashboard shows the correct state.
- `ApplyOutcome` contains the applied configuration and the active endpoint if the service is running. If the URL or credentials change, the dashboard prompts the user to update Zotero.

Test changes with the service stopped, port conflicts, startup failures, configuration write failures, and failed recovery.

## Proposed processing flow

1. The dashboard reads the current cloud folder, port, and credentials when the user opens **Advanced**. The user edits the values and applies the changes.
2. The backend validates the input and checks access to the destination folder. If the user selects a different port, the backend checks its availability. If WebDAV already holds the selected port, the restart step handles it.
3. If WebDAV is running, the backend keeps the current configuration for recovery, stops the old process, and launches rclone with the new configuration. If WebDAV is stopped, the backend saves the validated configuration for the next startup.
4. If the new process responds over WebDAV with the new credentials, the backend saves the configuration and returns the effective values. If startup fails, the backend attempts to restore the process with the previous configuration and reports the recovery result.
5. If the URL, username, or password changes, the dashboard displays the new values so the user can update Zotero and run **Verify Server** again.

Changing the folder changes the read and write destination for WebDAV. The handling of data in the old and destination folders needs approval before folder changes are implemented.

## Decisions before implementation

Decide whether users can select a folder that already contains data or migrate data when changing folders. Define the behavior if restoring the previous configuration also fails, and choose the release milestone for the Advanced panel.
